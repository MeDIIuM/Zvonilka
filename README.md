# Звонилка (iOS MVP)

MVP iOS-приложения:
- один главный экран;
- сетка контактов;
- сортировка по количеству начатых исходящих вызовов;
- быстрый вызов через системный dialer;
- локальное хранение без сервера.

## Что реализовано
- Доступ к контактам через `Contacts`
- Регистронезависимый поиск по имени/фамилии/номеру и русской транслитерации в обе стороны (например, «Саша» ↔ `Sasha`), клавиатура скрывается при скролле
- Поиск по всем номерам контакта и их части без учёта пробелов, скобок, дефисов и `+`; полный номер с `+7` также находится без кода страны и наоборот
- Звонок на введённый неизвестный номер без автоматического создания контакта; сохранение — через «Создать контакт»
- Сетка карточек контактов (`LazyVGrid` adaptive)
- Круглые аватары: фото контакта или инициалы
- Имя контакта до 2 строк с усечением
- Выбор номера при звонке — если у контакта несколько номеров, появляется action sheet
- Локальный счётчик начатых исходящих вызовов в `UserDefaults`: учитывается новый исходящий вызов, замеченный через `CXCallObserver` после запроса звонка; отмена подтверждения не увеличивает счётчик
- Системное подтверждение звонка открывается поверх сетки. При отмене и после возврата из звонка сразу доступна сетка, без промежуточного тёмного экрана. Счётчик и порядок обновляются при событии исходящего вызова из контактов в памяти, без ожидания загрузки адресной книги и без анимации перемещения. Если событие приходит уже после возврата, новый порядок применяется в этот момент
- Запрос звонка сохраняется при возврате из фона до события вызова, ошибки открытия ссылки, нового запроса или истечения системного времени наблюдения. Краткая активация приложения не считается отменой. Ограниченная фоновая задача даёт обработать начало вызова при переходе в Телефон; повторные события одного запроса не увеличивают счётчик
- Повторная загрузка не обновляет сетку, если данные для отображения не изменились; одновременные запросы объединяются, а устаревшие результаты отбрасываются
- Автообновление контактов при возврате приложения из фона
- Сортировка:
  1. больше исходящих выше
  2. при равенстве — по фамилии
  3. если фамилии нет — по имени
  4. если имени нет — fallback по номеру, затем в конец
- Настройки:
  - тема (системная / светлая / тёмная)
  - сброс счётчиков с подтверждением и тостом

## Ограничения MVP
- История звонков из системного приложения Телефон недоступна — Apple не предоставляет API
- `CXCallObserver` сообщает состояние текущих вызовов, но не номер: новый исходящий вызов сопоставляется с текущим запросом приложения. Считается начало вызова, а не ответ абонента; если событие не получено, по факту открытия ссылки счётчик не увеличивается
- Нет серверного хранения
- Нет аналитики/CRM
- Нет входящих звонков
- Нет кастомного редактирования контактов

## Сборка в Xcode
1. Клонируй репозиторий
2. Открой `Zvonilka/Zvonilka.xcodeproj`
3. Выбери симулятор или подключи iPhone
4. Запусти `Cmd+R`

Примечание: симулятор не совершает реальные звонки по `tel://`; наблюдение за началом вызова проверяется на iPhone.

## Проверка поиска

```sh
xcrun swiftc Zvonilka/Zvonilka/Models/ContactSearch.swift Tests/ContactSearchTests.swift -o /tmp/Zvonilka-contact-search-tests
/tmp/Zvonilka-contact-search-tests
xcrun swiftc Zvonilka/Zvonilka/Models/ContactItem.swift Zvonilka/Zvonilka/Models/CallDisplayState.swift Zvonilka/Zvonilka/Models/ContactListBuilder.swift Zvonilka/Zvonilka/Models/RawContact.swift Tests/ContactListUpdateTests.swift -o /tmp/Zvonilka-contact-list-tests
/tmp/Zvonilka-contact-list-tests
xcrun swiftc Zvonilka/Zvonilka/Models/CallAttemptState.swift Tests/CallAttemptStateTests.swift -o /tmp/Zvonilka-call-attempt-tests
/tmp/Zvonilka-call-attempt-tests
```

UI-тесты (`Cmd+U` в Xcode, схема `Zvonilka`) проверяют повторную отмену без тёмного экрана и лишних нажатий, доступность сетки при задержке события вызова, подтверждённый вызов со счётчиком +1 и перемещением карточки вверх, событие до ухода в фон и после возврата, краткую активацию перед уходом в фон, завершённый вызов без ответа и последовательность «отмена → звонок». Медленная повторная загрузка не должна откатывать счётчик и порядок. Только в Debug используются отдельные контакты, статистика в памяти, тестовое подтверждение вместо `tel://` и подмена транспорта событий CallKit; состояние запроса и экран — настоящие. Эти тесты не проверяют доставку событий настоящего CallKit на устройстве; системное подтверждение и начало звонка проверяются отдельно на iPhone.

Проверка на iPhone: нажать контакт → отменить → сетка сразу доступна, счётчик прежний; повторить и подтвердить вызов → после возврата прибавляется ровно один, тёмный экран отсутствует. Возврат без изменения данных не должен вызывать размытие или перезагрузку сетки. Значения, накопленные старой логикой учёта нажатий, можно обнулить в настройках.
